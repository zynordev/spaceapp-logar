# Render deployment (live demo)

The demo runs as one Docker web service (API + dashboard at `/ui/`) defined in `render.yaml`.
Demo data only; no real secrets are stored in the repository.

1. Push the repository to GitHub and sign in to Render with GitHub.
2. Render dashboard > New > Blueprint > pick this repository. Render reads `render.yaml`.
3. Confirm the service `spaceapp-logar` (free plan, Frankfurt). `SPACEAPP_AUTH_SECRET` is generated by Render;
   `SPACEAPP_DEMO_LOGIN=true` enables the one-click role login and `SPACEAPP_SEED_DEMO=true` seeds the demo.
4. Wait for the build (Docker, frontend + backend, several minutes) until the health check `/health` is green.
5. Open `https://<service>.onrender.com/ui/` and log in with a demo role.
6. On every boot the container runs migrations, imports the OSDR labs and seeds the co2-headache,
   chest-pain-red-flag and radiation-spe scenarios (radiation mission set to MARS when the profile API exists).
   The free plan has an ephemeral disk, so the database is rebuilt on each boot.
7. Warm-up before the jury: the free plan sleeps after ~15 minutes idle and a cold start takes about a minute.
   Open `/ui/` 5 minutes before presenting and click through once.
8. Keep-alive (optional): GitHub > Settings > Secrets and variables > Actions > Variables > add `DEMO_URL`
   (e.g. `https://<service>.onrender.com`). `.github/workflows/keepalive.yml` then pings `/health` every 10 minutes;
   without the variable it does nothing. It can also be started manually (workflow_dispatch). GitHub may disable
   scheduled workflows in inactive repositories; re-enable it in the Actions tab if so.
